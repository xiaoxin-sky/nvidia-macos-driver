UHD 770 手动应用计算测试候选包
============================

适用本机：i7-12700 / UHD 770 8086:4680 / x86_64 macOS 15。
这是实验候选包，没有本机运行成功证据。不是 UHD 770 桌面加速正式驱动。
本轮验证显示接管、真实 Vulkan 计算读回，以及前者通过后的 Metal 计算读回。
WindowServer、HiDPI 60 Hz、视频编解码、睡眠唤醒不属于本轮成功判据。

你只需要这样操作
----------------
1. 将整个 ZIP 带进 macOS 并解压。测试使用原来的 1401 U 盘，保持插着。
   先以原有 -nvoff 配置进入正常桌面；不要运行旧版 enable 或清空 NVRAM。
2. 打开终端，输入 sudo /bin/bash -p 后留一个空格，拖入本包根目录的
   Start-UHD770.command，再回车。按提示输入密码。
3. 程序在一次调用中验证包、私有 KC、USB 恢复目标、正常桌面日志（约 5 分钟），
   构建保留其他 /Library/Extensions 驱动的 KC、备份并安装本候选，最后才写入测试开关。
   准备可能需要十几分钟。没有 PREPARED 字样就不要重启测试。
   任一步失败会停止，尽力恢复改动并自动导出报告；不要自行删除 stage 或反复重跑。
   准备入口会从最早阶段记录完整终端输出。无论成功或失败，结束后都会尝试把该份
   日志复制到匹配 U 盘的 UHD770-prepare-logs/ 下；系统盘原件仍保留。
4. 看到 PREPARED 后，重启一次，通过同一个 1401 U 盘选择正常 macOS 15，照常登录。
   此前不需要另执行 enable。登录不会启动 Vulkan/Metal，也不会出现倒计时后自动测试。
   驱动自身仍按测试启动参数初始化：在固件可读后延迟 180 秒接管显示。
   本次改动是将计算测试改为手动，不是把内核驱动的初始化也推迟到点击命令之后。
   启动任务只恢复 U 盘的下次 -nvoff 配置，自动日志仍记录驱动初始化。
5. 登录后，由你决定何时开始。打开终端，用下面的方式运行本包根目录另一入口：

     sudo /bin/bash -p "/实际包路径/Run-UHD770-Test.command"

   与准备安装时一样，可以先输入 sudo /bin/bash -p 加空格，再拖入该文件。
   它会重新启动并检查一轮日志，核实恢复/初始化，然后在终端显示 Vulkan 阶段；
   Vulkan 计算读回通过才执行 Metal。驱动没初始化好、身份不匹配、失败或超时都会停止。
   root 只负责日志、恢复核验与导出；GPU 程序仍以准备时选定的普通用户运行。
6. 手动命令结束时显示 FINISHED 或 STOPPED，并收尾采集、打印完整报告位置：
   /Users/Shared/UHD770MVP-session-reports.XXXXXX。
   10 分钟只限制这次手动命令的最长运行时间，不从开机或登录开始倒计时。
   不必卡着登录时间运行；即使开机采集已经结束，手动入口也会重新启动有界采集。
   一次启动只允许执行一轮计算，重复点击会明确拒绝；保留现有日志，不要反复重跑。

如果黑屏/无信号，等信号消失后 6 分钟；仍无画面再手动重启。
同一个 U 盘的下一次正常 macOS 启动应已使用 -nvoff，自动导出留下的日志。
即使尚未手动执行计算，驱动初始化本身也可能导致黑屏。黑屏不能证明计算测试已开始。
黑屏不证明主机仍能工作；内核卡死/断电时日志可能不完整。

本手动版取消登录后的自动计算，准备时约 5 分钟的日志验证和接管前 180 秒延迟仍保留。
收尾时会短暂等待采集器写完最后标记，并补充快照，通常还需几秒；未收尾成功会标记 partial。

取回报告与恢复
--------------
准备阶段报错时，先查看 U 盘 UHD770-prepare-logs/ 下最新报告的 prepare.txt。
该文件包含早于安装/stage 的完整 STOP 报错，bootstrap-result.txt 记录退出码。
U 盘暂时不可用时，原件在 /Users/Shared/UHD770MVP-bootstrap.*；再次执行下面的
export 会把这些原件纳入汇总报告，无需重跑准备来复现。

bootstrap 原件是 root 专用的 700 权限目录，Finder 普通用户直接复制可能提示没有权限，
并留下空文件夹。不要修改原件权限；复制自动导出的 session-reports 或 U 盘
UHD770-prepare-logs 副本即可。

把最新的 /Users/Shared/UHD770MVP-session-reports.* 整个文件夹带回 Windows。
如果没有自动导出的文件夹，在正常桌面执行本包 tools/session.sh export：

  sudo /bin/bash -p "/实际包路径/tools/session.sh" export

本次 r5 日志自检失败后换包
-------------------------
本次已知失败发生在驱动安装之前：采集到约 300 秒，但缺少 collector_end 收尾标记。
修订包修复记录器正常结束和超时保护同时触发的竞态，保留独立的有限收尾保护。
正常桌面自检的时长、结束标记、成功查询与心跳门槛均没有放宽。

失败的旧暂存目录仍在，直接运行新 Start 会拒绝覆盖。先从新包显式运行：

  sudo /bin/bash -p "/实际包路径/Archive-UHD770-Failed.command"

它只接受干净 -nvoff 启动、未安装任何候选文件且恢复已成功的失败准备现场，
先导出报告，停止并检查旧记录器，再将完整旧暂存目录移动到唯一的 root 专用归档。
日志目录和启动配置不变，不删除现场，不启动测试；条件不满足会 STOP。
看到 ARCHIVED 后，在同一次正常桌面运行新包 Start-UHD770.command。
不需要为了归档重启；仍必须等新 Start 成功显示 PREPARED，才重启测试。

如果恢复启动仍有问题，回 Windows 执行包内 Restore-UHD770.ps1：

  powershell -NoProfile -ExecutionPolicy Bypass -File ".\Restore-UHD770.ps1"

它只在 FAT32/1401 卷及 config 哈希都匹配时恢复 -nvoff，不改分区或 macOS 文件。
文件被独立修改或有多个匹配 U 盘时会拒绝覆盖。请保留包内 session-target 目录。

需要把 macOS 驱动、固件、用户库和 AuxKC 恢复成安装前版本时，在正常 macOS 桌面：

  sudo /bin/bash -p "/实际包路径/tools/session.sh" restore

按白名单回放原始文件备份；不会在当前系统卸载正在运行的 GPU 驱动，下一次启动生效。
恢复中断后保留 journal，重复 restore 会跳过已完成条目。

具体边界
--------
- 不改 SIP/AMFI，不重置 NVRAM，不自动重启，不开启网络或全局 Metal 注入。
- 准备锁位于 /Library/Application Support/.com.uhd770.mvp.prepare.lock；
  不要求 /private/var/run 禁止系统组写入，也不会修改该系统目录的权限。
  准备成功/正常失败会清理自己创建的锁；断电留下的旧锁保留用于诊断，不自动删除。
- 不依赖 1401 的临时跳过选项；U 盘原始 -nvoff 配置字节另存并核对哈希。
- 不声称现在正在使用哪个 EFI；明确要求下一次从已核对的同一个 1401 USB 启动。
- 私有 stage/KC 仍是先决检查，但正常成功路径不再每个阶段要求人工返回交日志。
- NMXGPU 使用本机派生 ad-hoc 签名副本；原件保留。CLI 也只签派生副本并记录哈希。
  KC 链接和签名验证不能保证这台黑苹果的信任/加载策略允许实际加载。
- 不安装用户 LaunchAgent；普通用户 helper 没有 manual 参数时拒绝运行计算。
  准备时仅显式调用 preflight 核验可读性，重启只自动恢复/采集，手动入口才允许计算。
- 普通用户 helper 不能修改 EFI；手动 root 入口先核实恢复和新采集，再降权运行 probe。
- GPU 初始化失败时后续计算无法运行；超时会停止，不把未运行的测试记为通过。
- 用户态超时不能恢复内核死锁。自动日志与 USB 恢复仍需这次实机验证。
- session-target 包含机器配置，仅供本机使用；不要提交或公开上传整个包。
